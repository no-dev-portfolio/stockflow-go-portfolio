# 案件応募・面談での作品説明

## 作品紹介文

Go/GinとPostgreSQLを用い、在庫引当から出荷確定までを扱う自主制作「StockFlow」を作成しました。React/TypeScriptの日本語画面、REST APIとOpenAPI、組織・役割による認可、明細全体の取引、行ロックによる在庫超過防止、要求キーによる二重送信対策、期限解放、Outboxによる非同期処理と再試行を実装しています。

実PostgreSQLの複数接続で、在庫超過・二重登録・確定と取消の競合を試験し、Goのrace detector・静的検査・依存監査も実施しました。AWSについてはECS/Fargateと既存RDS等を使う構成例を用意し、Terraformの構成検査まで行っています。クラウド本番運用済みの作品ではありません。

## 面談で説明する順序

1. 製造業の在庫・販売管理の業務経験を背景に、どの業務条件を設計したか。
2. 単にmutexを置く代わりに、複数プロセスでも効くPostgreSQLのロックと制約を使う理由。
3. 同じキーに異なる内容を送った場合を409にする理由と、正規化の範囲。
4. ロック待機中に期限が経過する反例を一次審査で発見し、期限の確認位置を修正したこと。
5. 台帳・Outboxの原子性と、外部配送までexactly-onceとは言えない境界。
6. Goのcontext・goroutine終了、HTTPエラー・ログ・監視の考え方。
7. AWS未配備、固定デモキー等の残課題と本番化の順序。

## スキルシートに記載する場合

「自主制作：Go/Gin、PostgreSQL、React/TypeScript、Dockerを用いた在庫引当・出荷管理。API設計、SQL取引/競合対策、冪等性、非同期Outbox、テスト・品質検査を実装。AWS IaCは構成検査まで。」

業務経歴のURLとは別に、自主制作の公開先URLを記載する。公開先はまだ確定していないため、この段階で架空のGitHub URLを記入しない。Goの経験年数を実務として水増ししない。
