# 完成範囲と制約

- ローカル・架空データ専用。公開デモAPIキーは認証基盤の本番実装ではない。ユーザー登録、パスワード、OIDC、鍵ローテーションは未実装。
- 在庫マスターはデモ投入。仕入・補充・棚卸・複数倉庫・発注・ロット・返品・取消後の返金は実装しない。
- referenceは表示参照。異なる要求キーで同じreferenceを送ると別受注になる。業務の注文番号一意性は保証しない。
- Outbox処理先は同じDB内の台帳。外部配送・HTTP webhook・Kafka等のexactly-onceを保証しない。
- 期限判定点は行ロック確保後のDB時計確認。クライアントの表示・応答受信・厳密なコミット時刻による期限保証ではない。
- トランザクションの再試行はクライアントの同じキーで行う。全DB障害・ネットワーク断・強制停止で応答が不明にならないと保証するものではない。
- APIの一覧件数とサマリーは取得タイミングが異なる。リアルタイムで完全に同じスナップショットを返す設計ではない。
- 監査履歴の署名・改ざん防止・長期保全、バックアップ復旧、大規模負荷、全ブラウザー・支援技術への適合は未検証。
- DBユーザーはデモ初期化のDDL権限を持つ。本番には移行ロールとアプリロールを分離する必要がある。
- Terraformは構成検査のみ。AWS/GCPへの配備、plan、apply、運用・費用の検証は行っていない。
- GitHub Actions定義を同梱するが、リモートでの実行は今回未実施。GitHub公開も別の依頼で行う。
- Codexによる一次自己審査であり、独立した人間の監査・認証、Claudeのソース精読・フロントエンド検証報告は受領済みだが、Claude側のGo・実DB反証試験は未実施。
- この作品でGoの実務年数・チームでの開発経験を補ったと記載しない。
- ライセンスは作品固有の条件を未指定。Go/Gin/pgx/React等の依存は個別のライセンスに従う。

- 64KiBを超えるJSON本文は現行契約で400を返す（413ではない）。
- 同じ確定・取消への再送は正の古いversionでも成功し、新規の状態変更には現在version一致が必要。
